The Architecture of Atomicity

Harris-Fraser-Pratt Descriptor Objects in OCaml 5

Status: Active
mcas_types.ml
type status = Undecided | Succeeded | Failed
type word_desc = {
address : cell; // Memory location to update
old_value : Obj.t;
new_value : Obj.t;
parent : mcas_desc; // Back-pointer for status checks
}
and mcas_desc = {
status : status Atomic.t; // Primary CAS target
words : word_desc array;
retired : bool Atomic.t;
}

"The design utilizes OCaml's mutually recursive types to allow word descriptors to point back to their parent MCAS operation, facilitating cooperative 'helping' by multiple threads."

The Word Descriptor

Encapsulates the intent for a single memory location. It stores the expected value and the new value. The parent link is crucial: it allows any thread that encounters this word to find the global status.

The MCAS Descriptor

The Master Controller. While the operation affects $K$ locations, atomicity is achieved by performing a single CAS on the status field.

Key Technical Insight

  • Indirection: Memory slots (cells) don't just hold values; they can hold pointers to word_desc.
  • Atomicity Anchor: The status Atomic.t acts as the "Decision Point" for all $K$ updates.
  • Helping Protocol: If a thread sees a word_desc, it uses the parent link to complete the operation on behalf of the owner.
